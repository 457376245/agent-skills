# AGY 执行提示模板

将下列模板中的方括号内容替换为已预检的事实后，作为 `agy -p` 的 prompt。不要把未确认的猜测写入模板；没有值的可选项写为“未提供”。

```text
你是本次任务的实现执行者。请在主项目目录 [主项目绝对路径] 中完成以下任务：

[任务原文]

任务成功标准：
[验收标准]

允许使用的目录：
- 主项目：[主项目绝对路径]
- 额外目录：[额外目录列表；没有则写“无”]

上下文文件：
- 适用的 AGENTS.md：[路径列表]
- 需求追踪文档：[路径或“未提供”]
- 需求交接文档：[路径或“未提供”]

执行要求：
1. 先读取并遵守所有适用的 AGENTS.md；如果提供了需求追踪文档或交接文档，先读取它们并以其中已确认的范围、决定和验收标准为准。
2. 只做完成任务所需的最小、手术式修改，保护执行开始前已有的工作区修改；不要重置、暂存、覆盖或清理既有修改。
3. 只访问上面列出的目录。不要执行 commit、push、deploy，不要删除外部数据，不要修改未声明的项目或系统配置。
4. 先检查目标项目的当前状态；实现后运行与验收标准直接对应的验证。记录每条命令及其真实结果，并区分通过、失败、未运行和无法验证。
5. 如果需求文档存在会改变实现、接口、数据、权限或验收的实质性 TBD，停止实现并在结果中说明阻塞；不要自行补充答案。
6. 如果任务完成且提供了需求文档，更新实际文件、实施状态、验证、偏差和风险。将实施状态设为真实值；只有实现确实完成时才设为“已完成”，并将审查状态设为“待审查”，审查目标写成“未提交工作区 + 当前 HEAD SHA”。若阻塞或失败，保留真实状态，不要伪造交付。

最终只输出一个 JSON 对象，严格符合 result-schema.json。对象必须包含 status、summary、changed_files、verification、acceptance_evidence、requirement_doc、review_target、deviations、blockers 和 risks。不要输出 Markdown、前后解释或未声明字段。
```

当 agy 使用 `--output-format json` 时，CLI 可能把最终对象放在顶层 JSON 的 `structured_output` 字段中，并同时返回会话、响应和用量等 envelope 字段；这是正常的。调用方应验证 `structured_output` 是否符合 Schema，而不是要求 CLI envelope 本身只包含任务结果字段。

调用方应在模板外明确告知 agy：本次显式委派已授权其在声明目录内自动接受编辑；这不改变上述禁止 commit、push、deploy、越界访问和破坏既有修改的边界。
